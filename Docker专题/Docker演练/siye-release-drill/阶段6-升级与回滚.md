# 第七套准生产发布演练：阶段 6 真实升级与回滚

镜像构建、版本文件、双层 Nginx 和容器重建为什么能够生效，详见 [Docker 镜像从构建到运行生效链路](E:/本地项目/frontend-knowledge/Docker专题/Docker镜像从构建到运行生效链路.md)。

## 一、阶段目标与边界

本阶段默认只升级无状态前端镜像：

```text
siyesummer/siye-world:0.0.1
  -> siyesummer/siye-world:0.0.2
  -> siyesummer/siye-world:0.0.1
```

选择前端作为第一次升级对象，可以验证正式版本发布、镜像拉取、单服务重建、Nginx 上游刷新和回滚，同时不迁移数据库、不重建后端业务容器。

当前仍处于 ICP 备案和域名审核阶段，systemd Linux 主链路及其全部配置是不可变保护对象。本阶段：

- 不执行任何 systemd 写操作，包括 `stop`、`restart`、`disable`、`mask` 和相关 `daemon-reload`
- 不修改 systemd unit、环境文件、部署目录、端口、日志配置或宿主机现有 Nginx 配置
- 只允许用 `systemctl is-active` 做只读确认
- 不重建 `music-api`、`linux-server`、`easy-chat` 或 MySQL
- 不执行 `docker compose down`，更不能执行 `docker compose down -v`
- 只操作 `drill7-siye-world` 和 `drill7-edge-nginx`

## 二、0.0.2 发布门禁

服务器开始升级前，必须先在 `siyesummer/siyeWorld` 完成一个可验证的前端变更，并手动运行 `Release siye-world image`，默认选择 `bump=patch`。

必须确认：

- Git Tag / GitHub Release 为 `siye-world-image-v0.0.2`
- Docker Hub 同时存在 `siyesummer/siye-world:0.0.2` 和对应 commit SHA 标签
- 镜像支持 `linux/amd64`、`linux/arm64`
- `0.0.2` 仍从 `.env.production` 编译 `http://203.0.113.10:8090` 演练地址
- `0.0.2` 与 `0.0.1` 的源码 commit、镜像 ID 和 RepoDigest 可区分
- `0.0.2` 的 `/release.json` 返回 `version=0.0.2` 和本次发布 commit，OCI 标签包含相同的 `version/revision`
- 正式域名尚未完成 HTTPS 前，不把 `0.0.2` 提前改成正式域名版本

不能只把 `0.0.1` 的同一镜像改用 commit SHA 标签来冒充真实升级。如果 `0.0.2` 尚未发布，本阶段停在这里。

## 三、升级前只读检查与备份

在腾讯云 Linux 服务器执行：

```bash
cd /opt/docker-labs/siye-release-drill

docker compose --env-file .env -f compose.release-drill.yml ps

docker inspect --format \
  '{{.Name}} image={{.Config.Image}} image_id={{.Image}} status={{.State.Status}} health={{.State.Health.Status}} restarts={{.RestartCount}}' \
  drill7-music-api \
  drill7-linux-server \
  drill7-mysql \
  drill7-easy-chat \
  drill7-siye-world \
  drill7-edge-nginx

systemctl is-active music-api linux-server easy-chat

grep '^SIYE_WORLD_IMAGE=' .env
stat -c '.env permission=%a owner=%U:%G' .env
```

六个容器必须全部为 `healthy/0`，三个 systemd 服务必须为 `active`，当前前端必须仍为 `0.0.1`。

创建只包含演练环境的备份：

```bash
cd /opt/docker-labs/siye-release-drill

ENV_BACKUP=".env.before-phase6-$(date +%Y%m%d-%H%M%S)"
cp -p .env "$ENV_BACKUP"

docker image inspect siyesummer/siye-world:0.0.1 \
  --format 'BASE_IMAGE_ID={{.Id}} BASE_REPO_DIGESTS={{json .RepoDigests}}'

docker compose --env-file .env -f compose.release-drill.yml \
  exec -T mysql sh -c \
  'mysql -N -B -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" -e "SELECT CONCAT(\"BASE_CHAT_COUNT=\", COUNT(*), \" BASE_MAX_ID=\", COALESCE(MAX(id), 0)) FROM chat_message"'

echo "ENV_BACKUP=$ENV_BACKUP"
```

记录 `BASE_IMAGE_ID`、`BASE_REPO_DIGESTS`、`BASE_CHAT_COUNT`、`BASE_MAX_ID` 和备份文件名。

## 四、先拉取并检查 0.0.2

拉取新版本，但暂不修改运行容器：

```bash
docker pull siyesummer/siye-world:0.0.2

docker image inspect \
  siyesummer/siye-world:0.0.1 \
  siyesummer/siye-world:0.0.2 \
  --format '{{.RepoTags}} IMAGE_ID={{.Id}} REPO_DIGESTS={{json .RepoDigests}}'

docker image inspect siyesummer/siye-world:0.0.2 \
  --format 'LABELS={{json .Config.Labels}}'
```

如果 `0.0.2` 不存在、平台不匹配，或无法证明它是新的正式制品，停止升级，服务器 `.env` 保持不变。

## 五、修改版本并解析 Compose

```bash
cd /opt/docker-labs/siye-release-drill

sed -i \
  's#^SIYE_WORLD_IMAGE=.*#SIYE_WORLD_IMAGE=siyesummer/siye-world:0.0.2#' \
  .env

chmod 600 .env
grep '^SIYE_WORLD_IMAGE=' .env

docker compose --env-file .env -f compose.release-drill.yml \
  config --quiet \
  && echo '[OK] Compose 配置解析通过'

docker compose --env-file .env -f compose.release-drill.yml config --images
```

镜像列表只能发生 `siye-world:0.0.1 -> 0.0.2` 的变化，不得出现 `build:` 或其他业务镜像版本变化。

## 六、升级前端并刷新网关上游

先只重建前端：

```bash
docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate siye-world

for i in $(seq 1 12); do
  HEALTH="$(docker inspect --format '{{.State.Health.Status}}' drill7-siye-world 2>/dev/null || true)"
  echo "[$i/12] siye-world=$HEALTH"
  [ "$HEALTH" = healthy ] && break
  [ "$HEALTH" = unhealthy ] && break
  sleep 5
done

docker inspect --format \
  '{{.Name}} image={{.Config.Image}} image_id={{.Image}} status={{.State.Status}} health={{.State.Health.Status}} restarts={{.RestartCount}}' \
  drill7-siye-world
```

前端达到 `healthy/0` 后，只重建 edge-nginx：

```bash
docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate edge-nginx

for i in $(seq 1 12); do
  HEALTH="$(docker inspect --format '{{.State.Health.Status}}' drill7-edge-nginx 2>/dev/null || true)"
  echo "[$i/12] edge-nginx=$HEALTH"
  [ "$HEALTH" = healthy ] && break
  [ "$HEALTH" = unhealthy ] && break
  sleep 5
done
```

必须重建网关，因为 Nginx 静态 `proxy_pass` 会缓存前端容器重建前的 Docker IP。不能通过重启或修改 systemd 来处理网关 `502`。

## 七、0.0.2 升级验收

服务器验证：

```bash
curl --fail --silent --show-error http://127.0.0.1:8090/ | head -c 300
curl --fail --silent --show-error http://127.0.0.1:8090/log-query | head -c 300
curl --fail --silent --show-error http://127.0.0.1:8090/health
curl --fail --silent --show-error http://127.0.0.1:8090/release.json

curl --fail --silent --show-error --max-time 60 \
  'http://127.0.0.1:8090/music-api/search?keywords=test&limit=1&type=1' \
  -o /dev/null -w 'music-api HTTP %{http_code}\n'

curl --fail --silent --show-error --max-time 30 \
  'http://127.0.0.1:8090/api/logs/query?service=all&page=1&pageSize=3' \
  -o /dev/null -w 'linux-server HTTP %{http_code}\n'

curl --fail --silent --show-error --max-time 15 \
  -H 'Origin: http://203.0.113.10:8090' \
  'http://127.0.0.1:8090/socket.io/?EIO=4&transport=polling'
```

`/release.json` 必须返回 `version=0.0.2` 和本次发布 commit，并带有 `Cache-Control: no-store`。浏览器打开 `http://203.0.113.10:8090/`，验证版本变化、SPA 刷新、音乐、Socket.IO、聊天保存、历史读取和日志查询。发送一条唯一消息并记录 `message_id`，该消息用于回滚后的数据保留验证。

最后确认六个容器仍为 `healthy/0`，并且只读检查三个 systemd 服务仍为 `active`。

## 八、回滚到 0.0.1

升级验证通过后仍要主动执行回滚，不能把“能够修改 `.env`”当作已经验证回滚。

```bash
cd /opt/docker-labs/siye-release-drill

sed -i \
  's#^SIYE_WORLD_IMAGE=.*#SIYE_WORLD_IMAGE=siyesummer/siye-world:0.0.1#' \
  .env

chmod 600 .env
grep '^SIYE_WORLD_IMAGE=' .env

docker compose --env-file .env -f compose.release-drill.yml config --quiet

docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate siye-world
```

等待 `drill7-siye-world` 达到 `healthy`，再刷新网关上游：

```bash
docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate edge-nginx
```

再次验证：

- 容器 `.Config.Image` 为 `siyesummer/siye-world:0.0.1`
- 容器实际 image ID 与升级前记录的 `BASE_IMAGE_ID` 一致
- `0.0.1` 本身没有 `/release.json`，不能以该接口作为回滚判断依据；必须使用 image ID、RepoDigest 和业务基线
- `/`、`/log-query`、音乐、Socket.IO、聊天和日志接口仍正常
- 升级到 `0.0.2` 期间保存的消息仍能读取
- MySQL 中该 `message_id` 仍只有一条
- 六个容器全部 `healthy/0`
- 三个 systemd 服务仍为 `active`，全部 systemd 配置未改动

## 九、停止条件与紧急回滚

出现以下任一情况，停止继续验证并立即把 `SIYE_WORLD_IMAGE` 恢复为 `0.0.1`：

- `0.0.2` 镜像来源、Tag、digest 或平台不明确
- 前端容器 `unhealthy` 或持续重启
- 网关重建后仍持续出现 `502/504`
- `/log-query` 刷新 404
- 前端请求出现 localhost、错误端口或尚未启用的正式域名
- 音乐、Socket.IO、聊天、日志或 MySQL 数据发生回退
- Compose 计划重建前端和网关之外的服务

紧急回滚仍只允许操作 `siye-world` 和 `edge-nginx`。如果回滚失败，保留容器和日志用于排查，继续使用现有 systemd 主链路；不得修改 systemd 服务或配置来迁就 Docker 演练。

## 十、完成标准

阶段 6 只有同时满足以下条件才算完成：

- 实际运行过 `0.0.2`，不是同一制品换标签
- 完成 `0.0.2` 业务验收
- 实际回滚并运行 `0.0.1`
- 回滚后镜像 ID、健康状态和业务行为符合基线
- MySQL 数据在升级与回滚前后均保留
- systemd 服务及配置全程未改动
- 操作证据已写入 `验收清单.md`
