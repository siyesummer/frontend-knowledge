# 第七套准生产发布演练：阶段 3 easy-chat

## 一、阶段目标

本阶段只把已经正式发布的 `siyesummer/easy-chat:0.0.1` 加入第七套 Compose：

```text
Docker Hub
  -> docker compose pull easy-chat
  -> drill7-easy-chat
  -> 203.0.113.10:3130
  -> 本地 siyeWorld Socket.IO 联调
```

消息广播由 `easy-chat` 处理，消息持久化仍由浏览器调用阶段 2 的 `linux-server:8181`。`easy-chat` 不连接 MySQL，不加入 `data-net`。

本阶段不上传 easy-chat 源码，不上传 Dockerfile，不在服务器执行 `docker build`。原 `easy-chat.service` 继续监听 `3030`，Docker 版临时使用 `3130 -> 3030`。

## 二、上传包内容

本地 PowerShell 在 `E:\本地项目\frontend-knowledge` 执行：

```powershell
tar -czf "$env:TEMP\siye-release-drill-phase3.tar.gz" `
  -C "E:\本地项目\frontend-knowledge\Docker专题\Docker演练" `
  siye-release-drill

tar -tzf "$env:TEMP\siye-release-drill-phase3.tar.gz"
scp "$env:TEMP\siye-release-drill-phase3.tar.gz" ubuntu@203.0.113.10:/tmp/
```

上传包只能包含 Compose、`.env.example` 和演练文档，不能包含服务器 `.env`、业务源码、Dockerfile、JAR 或 `node_modules`。

## 三、服务器前置检查

在腾讯云 Linux 服务器执行：

```bash
echo '[INFO] 原 systemd easy-chat'
systemctl is-active easy-chat

echo '[INFO] 相关端口'
sudo ss -lntp | grep -E ':(3030|3130) ' || true

echo '[INFO] 第七套当前状态'
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml ps

docker inspect --format \
  '{{.Name}} image={{.Config.Image}} status={{.State.Status}} health={{.State.Health.Status}} restarts={{.RestartCount}}' \
  drill7-music-api drill7-linux-server drill7-mysql

stat -c '.env permission=%a owner=%U:%G' .env
df -h / /var/lib/docker
```

期望：

- `easy-chat.service` 为 `active`
- `3030` 由 systemd 版本监听
- `3130` 尚未被占用
- 阶段 1、2 三个容器仍为 `running/healthy`、`RestartCount=0`
- `.env` 权限为 `600`

任一条件不符合时先停止，不叠加启动新服务。

## 五、只向现有 `.env` 增加阶段 3 配置

```bash
cd /opt/docker-labs/siye-release-drill
nano .env
```

追加：

```dotenv
EASY_CHAT_IMAGE=siyesummer/easy-chat:0.0.1
EASY_CHAT_BIND_ADDRESS=0.0.0.0
EASY_CHAT_HOST_PORT=3130
EASY_CHAT_CORS_ALLOW_ORIGIN=http://localhost:8080,http://127.0.0.1:8080,http://siyefun.top,https://music.siyes.cn
```

如果本地 siyeWorld 实际端口不是 `8080`，必须加入真实 Origin。修改后检查重复键：

```bash
awk -F= '
  /^[A-Za-z_][A-Za-z0-9_]*=/ { count[$1]++ }
  END { for (key in count) if (count[key] > 1) print key, count[key] }
' .env

chmod 600 .env
```

没有输出才表示不存在重复配置键。

## 六、解析 Compose，暂不启动

```bash

docker compose --env-file .env -f compose.release-drill.yml \
  config --quiet \
  && echo '[OK] Compose 配置解析通过'

  config | grep -E 'image:|CORS_ALLOW_ORIGIN:|host_ip:|published:|target:'

  config | grep -q '^[[:space:]]*build:'; then

  echo '[OK] 不存在 build'

```

重点确认：

- `easy-chat` 使用 `siyesummer/easy-chat:0.0.1`
- 端口为 `0.0.0.0:3130 -> 3030`
- CORS 白名单包含真实前端 Origin
- `easy-chat` 只加入 `edge-net`
- 不存在 `build:`
- MySQL 仍没有宿主机端口

## 九、服务器本机验证

```bash
echo '[TEST] health'
curl --fail --silent --show-error --max-time 10 \
  http://127.0.0.1:3130/health
echo

echo '[TEST] 允许的 Socket.IO Origin'
curl --silent --show-error --max-time 10 \
  -D - -o /tmp/drill7-easy-chat-allowed.txt \
  'http://127.0.0.1:3130/socket.io/?EIO=4&transport=polling' \
  -H 'Origin: http://localhost:8080'
cat /tmp/drill7-easy-chat-allowed.txt

echo '[TEST] 未授权的 Socket.IO Origin'
curl --silent --show-error --max-time 10 \
  -D - -o /tmp/drill7-easy-chat-rejected.txt \
  'http://127.0.0.1:3130/socket.io/?EIO=4&transport=polling' \
  -H 'Origin: https://example.com'
cat /tmp/drill7-easy-chat-rejected.txt
```

允许来源应返回 `200` 和精确的 `Access-Control-Allow-Origin`；未授权来源应返回 `400`，且不能包含许可头。

## 十、本地电脑和 siyeWorld 真实联调

Windows PowerShell 先验证公网端口：

```powershell
curl.exe --noproxy "*" `
  --fail --silent --show-error --max-time 10 `
  "http://203.0.113.10:3130/health"

curl.exe --noproxy "*" `
  --fail --silent --show-error --max-time 10 `
  "http://203.0.113.10:3130/socket.io/?EIO=4&transport=polling"
```

然后把本地 siyeWorld Socket 地址临时改为：

```text
http://203.0.113.10:3130
```

Java API 仍使用：

```text
http://203.0.113.10:8181
```

至少验证：

- 页面成功建立 Socket.IO polling/WebSocket 连接
- 发送消息后实时显示
- `linux-server:8181` 保存请求返回 `200`
- 刷新页面后历史消息仍可读取
- 同一 `message_id` 在 MySQL 中只有一条
- `drill7-easy-chat` 日志出现 `connect` 和 `clientMsg`

如果服务器本机成功但本地失败，检查腾讯云安全组是否临时开放 TCP `3130`。统一入口完成后必须删除该规则。

## 十二、停止条件与完成标准

以下任一情况出现时停止阶段 3，并按 `回滚步骤.md` 只撤回 easy-chat：

- 容器为 `unhealthy` 或持续重启
- 未授权 Origin 得到 CORS 许可头
- 本地前端不能实时收发消息
- 消息持久化出现重复记录
- 原 systemd `3030` 链路或阶段 1、2 容器异常

所有检查通过并填写 `验收清单.md` 后，阶段 3 才完成，下一项进入 edge-nginx 统一入口。
