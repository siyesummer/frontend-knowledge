# 第七套准生产发布演练：阶段 1 music-api

## 一、阶段目标

本阶段只部署已经正式发布的 `siyesummer/music-api:0.0.1`，验证以下发布链路：

```text
GitHub Release / Docker Hub
  -> Linux docker compose pull
  -> drill7-music-api
  -> 203.0.113.10:3100
  -> 本地 siyeWorld 手工联调
```

本阶段不上传 music-api 源码，不上传 Dockerfile，不在服务器执行 `docker build`。原 `music-api.service` 继续监听宿主机 `3000`，第七套临时使用 `3100 -> 3000`，两套链路并行。

## 二、目录内容

本地材料目录：

```text
E:\本地项目\frontend-knowledge\Docker专题\Docker演练\siye-release-drill
```

服务器目标目录：

```text
/opt/docker-labs/siye-release-drill
```

阶段 1 只有以下文件：

```text
.env.example
.gitignore
compose.release-drill.yml
阶段1-发布演练.md
验收清单.md
回滚步骤.md
```

后续阶段再向同一 Compose 增加 MySQL、linux-server、easy-chat、edge-nginx 和 siye-world。

## 三、服务器前置检查

以下命令在腾讯云 Linux 服务器执行：

```bash
docker version
docker compose version
df -h / /var/lib/docker
systemctl is-active music-api
sudo ss -lntp | grep -E ':(3000|3100) ' || true
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
```

期望：

- `music-api.service` 仍为 `active`
- `3000` 由现有 systemd 服务使用
- `3100` 没有监听者
- 磁盘空间足够拉取约 152 MB 的镜像及解压后的镜像层

如果 `3100` 已被占用，先查清占用者，再修改 `.env` 中的 `MUSIC_API_HOST_PORT`；不要停止不认识的服务。

## 四、上传演练配置

这里只上传 Compose 和文档，不上传业务源码。本地 PowerShell 执行：

```powershell
tar -czf "$env:TEMP\siye-release-drill-phase1.tar.gz" `
  -C "E:\本地项目\frontend-knowledge\Docker专题\Docker演练" `
  siye-release-drill

tar -tzf "$env:TEMP\siye-release-drill-phase1.tar.gz"
scp "$env:TEMP\siye-release-drill-phase1.tar.gz" ubuntu@203.0.113.10:/tmp/
```

压缩包中不应出现 `.env`，只允许出现 `.env.example`。

## 五、服务器安装配置

在服务器执行：

```bash
rm -rf /tmp/siye-release-drill-phase1
mkdir -p /tmp/siye-release-drill-phase1
tar -xzf /tmp/siye-release-drill-phase1.tar.gz -C /tmp/siye-release-drill-phase1

test -f /tmp/siye-release-drill-phase1/siye-release-drill/compose.release-drill.yml
test -f /tmp/siye-release-drill-phase1/siye-release-drill/.env.example

sudo mkdir -p /opt/docker-labs
sudo chown ubuntu:ubuntu /opt/docker-labs

if [ -d /opt/docker-labs/siye-release-drill ]; then
  mv /opt/docker-labs/siye-release-drill \
    "/opt/docker-labs/siye-release-drill.bak-$(date +%Y%m%d-%H%M%S)"
fi

mv /tmp/siye-release-drill-phase1/siye-release-drill \
  /opt/docker-labs/siye-release-drill

cd /opt/docker-labs/siye-release-drill
cp .env.example .env
chmod 600 .env
nano .env
```

确认本地 siyeWorld 的实际地址。如果开发服务器不是 `http://localhost:8080`，必须同步修改 `MUSIC_API_CORS_ALLOW_ORIGIN`。Origin 包含协议和端口，`localhost` 与 `127.0.0.1` 也是两个不同 Origin。

## 六、解析 Compose，但不启动

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml config --quiet
docker compose --env-file .env -f compose.release-drill.yml config
```

重点确认：

- `image` 是 `siyesummer/music-api:0.0.1`
- 没有任何 `build:`
- 端口是 `3100:3000`
- CORS 白名单包含本地前端真实 Origin

## 七、只拉取正式镜像

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml pull music-api

docker image inspect siyesummer/music-api:0.0.1 \
  --format 'IMAGE_ID={{.Id}} REPO_DIGESTS={{json .RepoDigests}}'
```

把输出的 digest 记录到 `验收清单.md` 或本次演练记录中。后续联调和最终编排必须继续使用这一正式版本，不能在服务器重新构建一个同名镜像。

## 八、启动且禁止构建

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build music-api

docker compose --env-file .env -f compose.release-drill.yml ps
docker inspect --format \
  '{{.Name}} {{.Config.Image}} {{.State.Status}} {{.State.Health.Status}} {{.RestartCount}}' \
  drill7-music-api
```

期望容器最终达到：

```text
/drill7-music-api siyesummer/music-api:0.0.1 running healthy 0
```

## 九、服务器本机验证

```bash
curl --fail --max-time 10 http://127.0.0.1:3100/
curl --fail --max-time 60 \
  "http://127.0.0.1:3100/search?keywords=test&limit=1&type=1"

curl -i -X OPTIONS http://127.0.0.1:3100/search \
  -H 'Origin: http://localhost:8080' \
  -H 'Access-Control-Request-Method: GET'
```

预检应返回 `204`，并返回：

```text
Access-Control-Allow-Origin: http://localhost:8080
Vary: Origin
```

再验证未授权来源不会得到许可头：

```bash
curl -i -X OPTIONS http://127.0.0.1:3100/search \
  -H 'Origin: https://example.com' \
  -H 'Access-Control-Request-Method: GET'
```

## 十、本地电脑和前端验证

本地 PowerShell 先请求接口：

```powershell
curl.exe --fail --max-time 60 `
  "http://203.0.113.10:3100/search?keywords=test&limit=1&type=1"
```

然后只把本地 siyeWorld 的 music-api 基地址临时改为：

```text
http://203.0.113.10:3100
```

至少验证：

- 搜索返回结果
- 用户歌单等真实业务请求正常
- 浏览器 OPTIONS 为 `204`
- 响应的 `Access-Control-Allow-Origin` 等于本地前端 Origin，不是逗号列表
- 容器日志能看到对应请求且没有持续错误

如果服务器本机成功但本地电脑失败，优先检查腾讯云安全组是否临时允许 TCP `3100`。该规则应限制为当前本地公网 IP，不建议对所有来源长期开放。

## 十一、确认旧链路未受影响

服务器执行：

```bash
systemctl is-active music-api
curl --fail --max-time 60 \
  "http://127.0.0.1:3000/search?keywords=test&limit=1&type=1"
```

阶段 1 要求 systemd `3000` 和 Docker `3100` 同时可用，不修改 `music-api.siyes.cn` 当前 Nginx 上游。

## 十二、完成标准

完成所有验证后填写 `验收清单.md`。只有镜像来源、健康状态、CORS、本地前端和旧链路都通过，才进入 `linux-server:0.0.1` 发布准备。
