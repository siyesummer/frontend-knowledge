# 第七套准生产发布演练回滚说明

## 阶段 1 撤回

阶段 1 没有数据库和数据卷，撤回只需要删除第七套 music-api 容器和网络：

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml down
```

确认：

```bash
docker ps -a --filter name=drill7-music-api
sudo ss -lntp | grep ':3100 ' || true
systemctl is-active music-api
curl --fail --max-time 60 \
  "http://127.0.0.1:3000/search?keywords=test&limit=1&type=1"
```

不要删除 `siyesummer/music-api:0.0.1` 镜像。该镜像属于已经发布的正式制品，后续阶段还会继续使用。

## 阶段 2 撤回

阶段 2 回滚时保留阶段 1 `music-api`，只停止 Java 和 MySQL：

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml \
  stop linux-server mysql
```

确认旧链路仍可用：

```bash
systemctl is-active linux-server
curl --fail --max-time 10 \
  'http://127.0.0.1:8081/api/logs/query?service=all&page=1&pageSize=1'
docker inspect --format \
  '{{.Name}} {{.State.Status}} {{.RestartCount}}' \
  drill7-linux-server drill7-mysql
```

如果需要删除阶段 2 容器，但保留 MySQL 数据：

```bash
docker compose --env-file .env -f compose.release-drill.yml \
  rm -f linux-server mysql
docker volume ls | grep siye-release-drill
```

不要执行 `docker compose down -v`。`-v` 会删除阶段 2 MySQL 数据卷，不属于普通镜像回滚。正式镜像 `siyesummer/linux-server:0.0.1` 也应保留。

## 配置目录回滚

如果安装新配置前已经生成带时间戳的备份目录，可以执行：

```bash
cd /opt/docker-labs
mv siye-release-drill "siye-release-drill.failed-$(date +%Y%m%d-%H%M%S)"
mv siye-release-drill.bak-YYYYMMDD-HHMMSS siye-release-drill
```

先把 `YYYYMMDD-HHMMSS` 替换为真实备份目录名，不要直接复制执行占位命令。

## 阶段 3 撤回

阶段 3 回滚只停止并删除 `easy-chat` 容器，保留阶段 1、2 的 music-api、linux-server、MySQL 和数据卷：

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml \
  stop easy-chat
docker compose --env-file .env -f compose.release-drill.yml \
  rm -f easy-chat
```

确认临时端口已经释放，原 systemd 链路和已有容器仍正常：

```bash
sudo ss -lntp | grep ':3130 ' || true
systemctl is-active easy-chat
curl --fail --max-time 10 http://127.0.0.1:3030/health
docker inspect --format \
  '{{.Name}} {{.State.Status}} {{.State.Health.Status}} {{.RestartCount}}' \
  drill7-music-api drill7-linux-server drill7-mysql
```

不要执行 `docker compose down` 或 `docker compose down -v`；前者会同时停止阶段 1、2 容器，后者还会删除 MySQL 数据卷。

## 阶段 4 撤回

阶段 4 回滚只停止并删除 `edge-nginx`，保留 music-api、linux-server、MySQL、easy-chat 及数据卷：

```bash
cd /opt/docker-labs/siye-release-drill
docker compose --env-file .env -f compose.release-drill.yml \
  stop edge-nginx
docker compose --env-file .env -f compose.release-drill.yml \
  rm -f edge-nginx
```

确认 `8090` 已释放，三个临时直连入口和原 systemd 链路仍正常：

```bash
sudo ss -lntp | grep ':8090 ' || true
curl --fail --max-time 10 http://127.0.0.1:3100/
curl --fail --max-time 10 http://127.0.0.1:3130/health
curl --fail --max-time 10 http://127.0.0.1:8181/health
systemctl is-active music-api linux-server easy-chat
```

回滚后把本地 `siyeWorld/.env.local` 恢复到阶段 3 的 `3100/3130/8181` 地址并重启开发服务。不要执行 `docker compose down` 或 `docker compose down -v`。

## 阶段 5 撤回

阶段 5 失败时先把 edge-nginx 配置恢复为阶段 4 备份，再停止并删除前端容器：

```bash
cd /opt/docker-labs/siye-release-drill

cp /opt/docker-labs/siye-release-drill-backup-YYYYMMDD-HHMMSS/nginx/edge.conf \
  nginx/edge.conf

docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate edge-nginx

docker compose --env-file .env -f compose.release-drill.yml stop siye-world
docker compose --env-file .env -f compose.release-drill.yml rm -f siye-world
```

把 `YYYYMMDD-HHMMSS` 替换为阶段 5 开始前实际输出的备份目录。确认阶段 4 JSON 根路径和三条后端路由恢复：

```bash
curl --fail http://127.0.0.1:8090/
curl --fail --max-time 60 \
  'http://127.0.0.1:8090/music-api/search?keywords=test&limit=1&type=1'
curl --fail http://127.0.0.1:8090/api/logs/query?service=all\&page=1\&pageSize=1
curl --fail -H 'Origin: http://localhost:8080' \
  'http://127.0.0.1:8090/socket.io/?EIO=4&transport=polling'
```

阶段 5 新增的 `http://203.0.113.10:8090` CORS Origin 可以暂时保留，它不会改变阶段 4 行为；待演练全部结束再统一清理临时 Origin 和公网端口。不要删除正式镜像，也不要执行 `docker compose down -v`。

## 后续版本回滚原则

等 `0.0.2` 发布后，真实版本回滚通过修改服务器 `.env`：

```dotenv
MUSIC_API_IMAGE=siyesummer/music-api:0.0.1
```

然后执行：

```bash
docker compose --env-file .env -f compose.release-drill.yml pull music-api
docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --force-recreate music-api
```

回滚完成后必须重新检查健康状态、RestartCount、真实搜索接口、CORS 和容器日志。镜像回滚不会自动回滚数据库结构；后续加入 MySQL 后，数据库迁移必须保持向后兼容。

## 阶段 6 siye-world 紧急回滚

阶段 6 的完整步骤见 `阶段6-升级与回滚.md`。如果 `siye-world:0.0.2` 升级失败，只恢复前端版本并刷新网关上游：

```bash
cd /opt/docker-labs/siye-release-drill

sed -i \
  's#^SIYE_WORLD_IMAGE=.*#SIYE_WORLD_IMAGE=siyesummer/siye-world:0.0.1#' \
  .env

chmod 600 .env
docker compose --env-file .env -f compose.release-drill.yml config --quiet

docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate siye-world
```

等待 `drill7-siye-world` 恢复 `healthy` 后执行：

```bash
docker compose --env-file .env -f compose.release-drill.yml \
  up -d --no-build --pull never --no-deps --force-recreate edge-nginx
```

不得重建 MySQL 或三个后端业务容器，不得执行 `docker compose down` 或 `down -v`，不得修改、重启或停止任何 systemd 服务及其配置。
